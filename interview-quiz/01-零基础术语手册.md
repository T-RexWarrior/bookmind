# 零基础术语手册：从 RAG 到 Agent

> 用法：不要从头背到尾。先看每一节的“一句话记住”，再读“类比”，最后看“项目里对应什么”。面试前只看加粗句和“面试一句话”。

---

## 先说结论：这些词之间是什么关系

学一个 AI 应用，可以按这条线理解：

```text
大模型（LLM）
  ↓ 只能凭训练记忆回答，容易胡说
RAG（先检索资料，再让模型回答）
  ↓ 检索有很多种做法
关键词检索（BM25） + 语义检索（Embedding + 向量库）
  ↓ 把检索结果放进提示词
Prompt（提示词 / 上下文）
  ↓ 让模型不仅会回答，还能动手
Agent（模型 + 工具 + 循环）
```

所以：

- **RAG 不是向量数据库**。RAG 是一套“先查资料再回答”的流程，向量检索只是其中一种查法。
- **Agent 不是某个模型**。Agent 是“模型在循环里决定下一步做什么，并调用工具”的运行方式。
- **BM25 不是过时技术**。它是最可靠的关键词检索基线，尤其适合专有名词、代码、精确短语。

---

# 第一部分：模型基础

## 1. LLM（Large Language Model，大语言模型）

**一句话记住：一个根据上文预测下一个词的概率机器。**

**类比**：像输入法联想，只不过它读过的书极多，能连续联想出一整段看似有逻辑的话。

**它擅长**：总结、改写、解释、分类、生成代码、按格式输出。

**它不擅长**：保证事实正确、知道自己不知道、访问实时数据、记住你的私有资料。

**BookMind 里对应什么**：DeepSeek、OpenAI、Claude 等文字模型。项目不训练模型，只调用模型的 API。

**面试一句话**：LLM 是生成式模型，它没有内置的事实数据库，所以需要检索、工具和校验来补足可靠性。

---

## 2. Token（词元）

**一句话记住：模型眼里的“字块”，不是字，也不是词。**

**类比**：把一句话切成积木。英文里 `reading` 可能是一块，中文里一个字或两个字可能是一块。

**为什么重要**：

- API 按 token 计费。
- 上下文窗口按 token 限制。
- 输出也有 token 上限，超过会被截断。

**BookMind 里对应什么**：`MAX_ROUNDS`、`respond_max_tokens`、上下文预算、截断检测，都和 token 有关。

**面试一句话**：设计 Agent 时必须同时管理输入 token、输出 token 和轮数预算，否则成本和延迟会失控。

---

## 3. Prompt（提示词）

**一句话记住：你写给模型的“工作说明书”。**

**类比**：给一个很聪明但完全不了解你公司的实习生布置任务。你说得越清楚，他越不容易跑偏。

**一个 Prompt 通常包含**：

- 角色：你是谁
- 任务：要做什么
- 约束：不能做什么
- 上下文：资料、历史、工具结果
- 输出格式：JSON、Markdown、引用格式

**BookMind 里对应什么**：`bookmind/agents/*/prompts/`、`capabilities/reading/prompts/zh/reading.yaml`。系统提示词由多个 block 拼装，capability 可以插入自己的规则。

**面试一句话**：Prompt 不是“咒语”，而是接口设计；稳定的系统提示词加结构化的工具结果，比反复堆形容词更可靠。

---

## 4. Context Window（上下文窗口）

**一句话记住：模型一次能“看见”的 token 总量。**

**类比**：一张只能摊开固定大小的桌子。资料太多，就必须挑重点放上来，或者先做摘要。

**窗口里有什么**：

- 系统提示词
- 对话历史
- 检索到的资料
- 工具调用和工具结果
- 本次用户问题

**超了会怎样**：报错、截断、或者模型忘记前面内容。

**BookMind 里对应什么**：

- `CONTEXT_WINDOW_GUARD_RATIO = 0.9`：用到 90% 就开始压缩/裁剪。
- 阅读定位只注入 4 条命中，每条 260 字符，避免挤占对话。
- 系统提示词尽量保持稳定，利于缓存。

**面试一句话**：上下文不是越大越好；关键是“把最相关的信息放在最显眼的位置”，并给上下文设预算。

---

## 5. Hallucination（幻觉）

**一句话记住：模型一本正经地编造不存在的事实、引用或页码。**

**类比**：一个记忆力很好但爱面子的人，不知道答案时也不说“不知道”，而是现场编一个。

**常见形态**：

- 编造论文、作者、年份
- 编造代码 API
- 声称“第 12 页写了……”但根本没读
- 引用一段原文，实际原文没有这句话

**怎么缓解**：

1. 检索增强（RAG）
2. 强制引用来源
3. 工具返回结构化证据
4. 对引用做程序校验
5. 允许模型说“资料中没有”

**BookMind 里对应什么**：

- 阅读工具返回带 locator 的原文片段。
- `reader_goto` 会校验 quote 是否真的出现在文档里；不匹配就不高亮。
- 未验证的浏览器文本不会写入学习状态。

**面试一句话**：防幻觉不能只靠提示词，要把“证据”做成系统能力：能检索、能定位、能校验、能拒绝。

---

## 6. Streaming（流式输出）

**一句话记住：模型边生成，页面边显示，而不是等全部生成完再一次性返回。**

**类比**：服务员一道一道上菜，而不是等所有菜做完才端上来。

**技术形态**：SSE、WebSocket、HTTP chunked。

**BookMind 里对应什么**：FastAPI 通过 WebSocket/流式事件把文字、工具调用、引用、图解推给 Next.js 前端。

**面试一句话**：流式输出改善首字延迟和可感知性能，但也要求前后端都能处理“半成品”状态和工具事件。

---

# 第二部分：RAG 与检索

## 7. RAG（Retrieval-Augmented Generation，检索增强生成）

**一句话记住：先查资料，再让模型带着资料回答。**

**类比**：开卷考试。模型不是凭记忆答题，而是先翻书找到相关段落，再组织答案。

**标准流程**：

```text
文档 → 解析 → 切块（chunk）→ 建索引（embedding / 关键词）
                                      ↓
用户问题 → 检索（retrieve）→ 重排（rerank）→ 拼进 Prompt → 模型生成 → 引用
```

**RAG 解决什么**：

- 模型训练数据过时
- 私有资料模型没见过
- 需要可追溯的引用
- 降低幻觉

**RAG 不解决什么**：

- 检索不到的内容，模型仍然可能编
- 检索到错误内容，模型会被带偏
- 多跳推理、冲突信息、权限控制仍然需要额外设计

**BookMind 里对应什么**：

- 阅读模式：不做向量检索，直接用“定位 + 全文扫描”找到原文，再让模型回答。
- 知识库模式：保留 LlamaIndex 的向量/BM25/混合检索与 PageIndex 适配器。
- AI 导学：准备小节时先检索原文证据，再规划学习目标。

**面试一句话**：RAG 的核心不是“接一个向量库”，而是“让回答有可验证的依据”。检索方式要服从场景。

---

## 8. Retrieval（检索）

**一句话记住：从一堆资料里，找出和问题最相关的几段。**

**类比**：在图书馆里找书。你可以按关键词找（书名/索引），也可以按“意思相近”找（管理员凭理解推荐）。

**评价指标**：

- Recall@K：正确答案有没有出现在前 K 条里
- Precision@K：前 K 条里有多少是相关的
- MRR / NDCG：相关结果排得靠不靠前
- 端到端：回答是否正确、引用是否真实

**BookMind 里对应什么**：`search_material`、`RAGService.search`、`retrieve_nodes`。

**面试一句话**：先保证召回，再谈排序；召回不到，后面的模型再强也没用。

---

## 9. Chunk（文本块）

**一句话记住：把长文档切成模型能处理的小段。**

**类比**：把一本厚书拆成一页页卡片。每张卡片要能独立读懂，又不要大到一次拿不动。

**关键参数**：

- `chunk_size`：每块多大（字符/token）
- `chunk_overlap`：相邻块重叠多少，避免一句话被切断
- 切分方式：固定长度、按段落、按标题、按语义

**BookMind 里对应什么**：LlamaIndex 配置默认 `chunk_size=512`、`chunk_overlap=50`；阅读模式则按“页/节/单元”存储，天然带定位。

**面试一句话**：Chunk 是检索质量的地基。块太大，噪音多；块太小，语义不完整；重叠是折中。

---

## 10. Embedding（嵌入 / 向量化）

**一句话记住：把一段文字变成一串数字，让“意思相近”变成“距离相近”。**

**类比**：给每段文字在一个巨大的地图上标一个坐标。讲“栈”的段落和讲“后进先出”的段落，坐标会靠得很近。

**注意**：

- Embedding 不是加密，也不是压缩，它是语义特征的数值表示。
- 需要专门的 embedding 模型（和聊天模型不是一回事）。
- 同一个模型产出的向量才能互相比较。
- 换 embedding 模型通常要重建索引。

**BookMind 里对应什么**：`bookmind/services/embedding`、`embedding_adapter.py`、`embedding_signature.py`。索引版本会记录 embedding 配置，避免“旧向量用新模型查”。

**面试一句话**：Embedding 把语义检索变成向量近邻搜索；模型、维度、归一化方式必须一致，否则索引会失效。

---

## 11. Vector（向量）

**一句话记住：一串有方向的数字，例如 `[0.12, -0.83, 0.44, ...]`。**

**类比**：地图上的坐标。二维坐标能表示位置，几百维坐标能表示“语义位置”。

**相似度怎么算**：

- 余弦相似度：看夹角，最常用
- 点积：看方向和长度
- 欧氏距离：看直线距离

**BookMind 里对应什么**：FAISS 向量索引、`VectorStoreIndex`、`embedding_dict`。

**面试一句话**：向量检索的本质是最近邻搜索；高维空间里精确搜索很贵，所以常用近似算法。

---

## 12. Vector Database / FAISS（向量库）

**一句话记住：专门存向量、并按相似度快速找邻居的系统。**

**类比**：一张按语义坐标排好的巨型地图，能快速找到你附近的点。

**常见产品**：FAISS、Milvus、Qdrant、Weaviate、pgvector。

**FAISS 是什么**：Facebook 开源的向量检索库，不是完整数据库；它负责索引和搜索，元数据通常还要自己存。

**BookMind 里对应什么**：`faiss-cpu`、`llama-index-vector-stores-faiss`。默认 flat 精确索引，也支持 HNSW 参数。

**面试一句话**：向量库解决“大规模语义近邻”问题；小数据量下，暴力扫描反而更简单可靠。

---

## 13. Cosine Similarity（余弦相似度）

**一句话记住：看两个向量方向像不像，不看长度。**

**类比**：两个人描述同一件事，用词多少不同，但方向一致，就算相似。

**公式直觉**：

```text
cos(a, b) = (a · b) / (|a| × |b|)
```

结果越接近 1 越相似。

**面试一句话**：文本 embedding 常做归一化，再用余弦或点积；归一化后两者等价。

---

## 14. ANN / HNSW（近似最近邻）

**一句话记住：为了快，允许“差不多最近”，不保证绝对最近。**

**类比**：在巨大城市里找最近的咖啡店，不需要量遍每一家，走几张“高速公路”就能找到附近区域。

**HNSW**：分层可导航小世界图，用多层图结构做近似搜索。参数 `M`、`efConstruction`、`efSearch` 影响召回和速度。

**权衡**：召回率 vs 延迟 vs 内存。

**BookMind 里对应什么**：`VectorIndexConfig` 支持 `flat` 和 `hnsw`，默认 flat。

**面试一句话**：数据量小用精确搜索，数据量大用 ANN；ANN 要监控召回率，不能只看延迟。

---

## 15. BM25（Best Matching 25）

**一句话记住：按“关键词出现得多不多、稀不稀罕、文档长不长”给文档打分。**

**类比**：查词典。一个词在文档里出现次数多，说明相关；但如果这个词满大街都是（如“的”），权重就低。

**BM25 的三个直觉**：

1. **TF（词频）**：查询词在文档里出现越多，分数越高，但增长会饱和。
2. **IDF（逆文档频率）**：越罕见的词，权重越高。“栈”比“是”更有区分度。
3. **文档长度归一化**：长文档天然容易包含更多词，要惩罚一下，避免长文占便宜。

**BM25 擅长**：

- 专有名词、人名、错误码
- 代码标识符、API 名
- 精确短语
- 不需要 GPU、可解释、稳定

**BM25 不擅长**：

- 同义词（“栈” vs “后进先出”）
- 改写后的自然语言问题
- 跨语言
- 中文分词错误会直接影响效果

**BookMind 里对应什么**：

- `llama-index-retrievers-bm25`、`bm25s`
- 混合检索中的关键词分支
- legacy page BM25 路径

**面试一句话**：BM25 是关键词检索的强基线；它不理解为“意思”，但正因为如此，精确匹配时非常可靠。

---

## 16. TF / IDF

**一句话记住：TF 是“这个词在这篇里多不多”，IDF 是“这个词在整个资料库里稀不稀罕”。**

**类比**：

- TF：这篇文章里“二叉树”出现了 20 次，说明它可能是主题。
- IDF：“二叉树”在 1000 篇里只出现 3 次，说明它很有区分度；“的”到处都是，权重应接近 0。

**面试一句话**：BM25 用 TF 衡量局部相关，用 IDF 衡量全局区分度，再加长度归一化。

---

## 17. Hybrid Retrieval（混合检索）

**一句话记住：关键词检索和语义检索一起上，取长补短。**

**类比**：找餐厅时，一边按“菜名关键词”搜，一边按“我想吃清淡的”这种语义推荐，最后合并两份名单。

**为什么需要**：

- 向量检索擅长语义，但可能漏掉精确名称
- BM25 擅长精确词，但不懂同义改写
- 两者失败模式不同，合并后更稳

**怎么合并**：

- 分数加权
- 倒数排名融合（RRF）
- 先各自召回，再统一 rerank

**BookMind 里对应什么**：`QueryFusionRetriever`，`FUSION_MODES.RECIPROCAL_RANK`，默认 `hybrid` profile；BM25 不可用时自动降级为纯向量。

**面试一句话**：混合检索的价值在于“不同检索器的错误不相关”，融合后召回更稳；代价是复杂度和延迟。

---

## 18. RRF（Reciprocal Rank Fusion，倒数排名融合）

**一句话记住：不看原始分数，只看排名，把多个榜单合成一个。**

**类比**：三个评委分别给选手排名，不比较他们的打分标准，只把名次相加。

**公式**：

```text
score(d) = Σ 1 / (k + rank_i(d))
```

`k` 是平滑常数（常见 60）。

**好处**：不同检索器的分数尺度不同，直接相加没意义；RRF 只看名次，简单稳健。

**面试一句话**：RRF 解决“向量分数和 BM25 分数不可比”的问题，是混合检索常用的无监督融合方法。

---

## 19. Rerank（重排）

**一句话记住：先粗筛一批候选，再用更贵的模型精排。**

**类比**：招聘先按关键词筛简历（快、粗），再让面试官逐份细看（慢、准）。

**常见做法**：Cross-Encoder 把“问题 + 文档”一起输入模型，直接输出相关性分数。

**权衡**：效果好，但比向量检索慢很多，所以只对前 20-100 条候选做。

**BookMind 里对应什么**：`rerank.py`、`reranker_model`、`rerank_top_k`，默认不启用，配置后才精排。

**面试一句话**：Rerank 是“召回后精排”，用延迟换准确率；没有 rerank 时，检索器的 top-k 就是最终结果。

---

## 20. Recall@K / Faithfulness（评估）

**一句话记住：先看“该找到的有没有找到”，再看“回答有没有依据”。**

**Recall@K**：正确答案是否出现在前 K 条检索结果里。

**Faithfulness**：回答中的每个关键结论，是否都能在检索到的证据里找到支持。

**Citation Accuracy**：引用的页码、句子是否真实存在。

**BookMind 里对应什么**：

- 阅读工具返回 locator，引用可校验。
- `reader_goto` 对 quote 做存在性校验。
- 学习证据只在已验证的原文范围内写入。

**面试一句话**：RAG 评估要分层：检索层看 recall，生成层看 faithfulness，产品层看引用准确率和用户是否真的学会了。

---

# 第三部分：Agent

## 21. Agent（智能体）

**一句话记住：会自己决定“下一步做什么”，并能调用工具完成任务的模型系统。**

**类比**：不是只会聊天的客服，而是能查订单、改地址、发邮件的客服。

**Agent 的四个部件**：

1. 模型：负责推理和决策
2. 工具：负责真正执行动作
3. 循环：观察结果，决定继续还是结束
4. 状态/记忆：保存对话、任务进度、用户信息

**Agent 与普通聊天**：

| 普通聊天 | Agent |
| --- | --- |
| 一次生成 | 多轮“思考—行动—观察” |
| 只能输出文字 | 可以调用工具 |
| 不能改变外部世界 | 可以读写文件、查库、发请求 |
| 出错只能重说 | 可以根据工具结果纠错 |

**BookMind 里对应什么**：`AgentLoop`、`AgenticLoopPipeline`、capability 工具集。

**面试一句话**：Agent 的核心不是“多智能体”，而是“模型能否在循环里根据工具反馈做决策”。

---

## 22. Tool Calling（工具调用 / Function Calling）

**一句话记住：模型不直接执行代码，而是输出“我要调用哪个工具、参数是什么”，由后端执行。**

**类比**：经理说“去查一下这个订单”，但真正查系统的是助理。经理只下指令。

**流程**：

```text
模型输出 tool_call(name, arguments)
        ↓
后端校验参数、权限、注入上下文
        ↓
执行工具
        ↓
把结果作为 role=tool 消息放回对话
        ↓
模型继续推理
```

**为什么不让模型直接执行**：安全、权限、可审计、可重试、可并行。

**BookMind 里对应什么**：

- `ToolDefinition` / `ToolParameter` / `ToolResult`
- `dispatch_tool_calls` 并行执行，最多 15 个
- `augment_kwargs` 在服务端注入 `material_id`，模型不能自己指定没打开的文档

**面试一句话**：工具调用的关键设计是“模型只提议，系统来执行和校验”；参数注入和权限边界必须在服务端。

---

## 23. Agent Loop（智能体循环）

**一句话记住：一轮 LLM 调用 → 有工具就执行并继续 → 没工具就结束。**

**BookMind 的实际规则**：

- 一次用户提问 = 一个不断增长的对话
- 每一轮 = 一次 LLM 调用
- 这一轮调用了工具：模型写的是“旁白/计划”，工具结果追加进对话，继续下一轮
- 这一轮没有调用工具：这就是最终回答，循环结束
- 默认最多 8 轮探索；预算用完还有 3 轮结算；最后强制一次无工具收尾
- `ask_user` 可以暂停循环，等用户回答后继续

**为什么要设上限**：防止死循环、成本爆炸、延迟不可控。

**面试一句话**：Agent Loop 是“带预算的 while 循环”；产品化时必须设计轮数、token、超时、重试和终止条件。

---

## 24. ReAct（Reason + Act）

**一句话记住：让模型交替“想一想”和“做一步”。**

**类比**：解数学题时，先想思路，再动笔算一步，看结果，再想下一步。

**典型轨迹**：

```text
Thought: 我需要先找定义
Action: search_material("栈")
Observation: 第 4.1 节……
Thought: 还需要看实现
Action: read_material("4.1")
Observation: ……
Answer: ……
```

**BookMind 里对应什么**：Agent loop 的每一轮文本就是 commentary，工具调用就是 action，工具结果就是 observation。

**面试一句话**：ReAct 把推理和执行交织起来，比“一次性生成”更适合需要查证的任务。

---

## 25. Memory（记忆）

**一句话记住：Agent 记住什么、记多久、怎么取出来。**

**几种记忆**：

- 短期：当前对话历史
- 工作记忆：本次任务的中间结果、工具输出
- 长期：用户偏好、学习记录、笔记、知识库
- 语义记忆：向量库/知识图谱

**BookMind 里对应什么**：

- 会话历史（`conversation_history`）
- 学习状态（掌握度、错题、复习队列）
- 笔记（notebook）
- 教材关联（material_id / path_id）
- 可选记忆工具（`read_memory` / `write_memory`）

**面试一句话**：记忆不是“把所有历史都塞进上下文”，而是分层存储、按需检索、控制写入边界。

---

## 26. MCP（Model Context Protocol）

**一句话一句话记住：给模型/Agent 连接外部工具和数据源的一套标准协议。**

**类比**：USB 接口。不同厂商的设备，只要遵守同一套接口，就能插到同一台电脑上。

**它解决什么**：工具接入碎片化。以前每个 Agent 框架都要自己写一套工具适配；MCP 把“工具、资源、提示词”标准化。

**BookMind 里对应什么**：依赖中有 `mcp`，可以挂载 MCP 工具；但项目核心不是 MCP 示范项目。

**面试一句话**：MCP 是 Agent 工具生态的“接口标准”，价值在于复用和互操作，不是新的模型能力。

---

## 27. Orchestration（编排）

**一句话记住：决定“先做什么、谁来做什么、失败了怎么办”。**

**类比**：餐厅后厨的调度。谁切菜、谁炒菜、哪道菜先上、客人催单怎么办。

**编排要处理**：

- 路由：这个问题该走哪个能力
- 预算：轮数、token、时间
- 并行：哪些工具可以同时跑
- 重试/降级：模型或工具失败怎么办
- 人工介入：什么时候停下来问用户
- 状态：任务进行到哪一步

**BookMind 里对应什么**：`AgenticLoopPipeline`、capability 激活、`dispatch_tool_calls`、settlement 阶段、`ask_user` 暂停。

**面试一句话**：Agent 产品化的难点不在“调模型”，而在编排：边界、预算、失败恢复和可观测性。

---

## 28. Guardrail（护栏）

**一句话记住：给 Agent 设“不能越过的线”。**

**类比**：高速公路的护栏。不是限制你开车，而是防止你冲出路面。

**常见护栏**：

- 权限：不能读没打开的文档
- 参数：工具参数必须校验
- 引用：quote 必须真实存在
- 内容：敏感信息、提示词注入
- 预算：最大轮数、最大 token、超时
- 写入：未验证内容不能改学习状态

**BookMind 里对应什么**：`_guard`、`augment_kwargs`、`verify_quote`、`session_scope`、`learning_material_allowed`。

**面试一句话**：护栏要写成代码，不要只写在 Prompt 里；Prompt 会被绕过，代码不会。

---

## 29. Grounding / Citation（依据与引用）

**一句话记住：回答里的每个关键结论，都能指回一段真实存在的原文。**

**类比**：写论文时的脚注。不是“我觉得是这样”，而是“见第 4 章第 2 节”。

**为什么重要**：

- 用户可以验证
- 出错时能定位
- 模型更难编造
- 产品可信度更高

**BookMind 里对应什么**：

- 阅读工具返回 `locator`（页码/章节/幻灯片号）
- 引用格式 `[p.N]` 或时间戳
- `reader_goto` 跳转并高亮
- 高亮前校验 quote

**面试一句话**：Grounding 不是让模型“记得加引用”，而是让检索结果天然携带定位信息，并让系统校验引用。

---

## 30. Multi-Agent（多智能体）

**一句话记住：多个 Agent 分工协作，而不是一个 Agent 包打天下。**

**类比**：一个团队里有人查资料、有人写代码、有人审查。也可以一个人全做，但分工可能更专业。

**常见模式**：

- 主管 Agent 分派任务
- 专家 Agent 各自处理
- 结果汇总/辩论/投票

**代价**：

- 通信成本
- 状态一致性
- 错误传播
- 调试困难

**BookMind 的选择**：以单 Agent 循环为主，用 capability 插件扩展能力；多智能体不是默认架构。

**面试一句话**：多智能体不是越复杂越好；当单 Agent 的工具和上下文还能管理时，优先单 Agent。

# 最容易混淆的 6 组概念

## 1. RAG ≠ 向量数据库

RAG 是流程，向量库只是检索的一种实现。BookMind 的阅读模式甚至不用向量库，而是用带定位的全文扫描。

## 2. Embedding ≠ 加密

Embedding 是把语义变成向量，目的是计算相似度；它不是可逆加密，也不是压缩。

## 3. BM25 ≠ 向量检索

BM25 看词是否出现、出现多少、词有多稀有；向量检索看语义坐标是否接近。两者失败模式不同，所以可以混合。

## 4. Agent ≠ 工作流

工作流是预先写死的步骤；Agent 是模型在循环里根据观察决定下一步。很多“Agent 产品”其实是工作流 + 少量模型调用，这并不丢人，反而更可控。

## 5. 微调 ≠ RAG

微调改变模型参数，适合学风格/格式/领域行为；RAG 不改模型，适合接私有知识和实时资料。大多数“让模型懂我们公司文档”的需求，优先 RAG。

## 6. 上下文窗口 ≠ 记忆

上下文窗口是模型一次能看到的 token 上限；记忆是系统怎么存、怎么取。窗口大不代表会记住，记忆需要工程化。

# 面试前 10 分钟只看这一段

```text
RAG：先检索，再生成。不是向量库的同义词。
BM25：关键词打分，TF × IDF × 长度归一化。精确、可解释、怕同义词。
向量检索：Embedding 把语义变成坐标，找最近邻。擅长同义改写，怕精确名称。
混合检索：两路召回 + RRF 融合；可选 rerank 精排。
Agent：模型 + 工具 + 循环 + 状态。模型提议，系统执行。
Agent Loop：有工具就继续，没工具就结束；必须有轮数/ token / 超时预算。
护栏：权限、参数、引用校验、写入边界，写成代码而不是只写 Prompt。
BookMind 的选择：阅读用 locator 全文检索；知识库保留向量/BM25/混合；单 Agent + capability。
```
