# AI + 教育比赛演示建议（约 8 分 40 秒）

具体界面与功能均对应本版实现。主线使用大学《数据结构》中的二叉树遍历，模拟一个会背定义、但容易混淆访问时机的学生。

## 0:00–1:30　作品概述

展示首页两个入口。

解说：“我们做的是 BookMind（学迹），一个围绕资料与学习目标展开的 AI 学习助手。大学生自学时经常遇到三个问题：教材看过却没有真正读懂，问完 AI 不知道自己会不会，以及对话里的理解很难整理和回顾。BookMind 把阅读、讲解、图解、练习和笔记放在同一个学习空间，并让它们都能回到原文。”

强调只有两种起点：带资料来，或说出学习目标。三个工作页面：学习、练习、笔记。不要在概述中展开接口、模型参数和框架名称。

## 1:30–3:00　读教材，带着原文提问

1. 上传一份可复制文字的 PDF；也可以打开已准备的二叉树示例资料。
2. 跳转“三种深度优先遍历”一节，展示左侧目录和中间原文。
3. 划选中序遍历定义，输入：“我把前序和中序搞混了，能用最简单的例子讲清楚吗？”
4. 展示实际流式回答，点击来源按钮回到原文。

解说重点：“提问时不必重新复制整段教材。系统知道我正在读哪份资料的哪一节；讲解也保留来源，便于核对。”

## 3:00–4:20　用过程图解看懂访问时机

输入：“用分步图演示 A(B(D,E),C) 的中序遍历，显示递归与输出顺序。”点击“画图理解”。

展开图解，手动走前两步，再点击播放，观察当前节点与已访问节点，说明“递归进入一个节点”和“把节点加入输出”不是一回事。保存图解到笔记。

解说重点：“抽象规则变成可以暂停和回退的具体过程。学生可以在卡住的那一步停下来思考。”

## 4:20–5:50　练习检验，定位还没想清楚的点

1. 点击“练习本节”，在独立练习页输入“中序与前序的区别”，生成三道理解题。
2. 一题独立作答；另一题使用提示后再答。若答错，展示解析与原文依据。
3. 点击原文来源，回到对应章节；将一个容易混淆的问题保存为笔记。
4. 展示练习记录与知识点学习记录。

解说重点：“系统记录的不是 AI 对我的主观印象，而是具体做过哪些题、是否使用提示、第一次答得怎样。题目太少时，只能说明本次表现，不能直接声称已经全面掌握。”

## 5:50–6:40　把讲解变成自己的笔记

打开笔记页，找到保存的图解。添加自己的总结：“中序不是一进入节点就输出，要先处理完左子树。”保存、预览，点击“回到学习现场”。可以导出 Markdown 展示可带走的学习成果。

解说重点：“笔记里保留的是自己的理解，也保留当时的图解和教材位置，后面复习时能找回上下文。”

## 6:40–7:30　没有教材，也能从目标开始

回首页，输入：“我是大一学生，想理解 Python 递归、终止条件和调用栈。”生成四节短手册，展示目录与正文，说明这份手册也能进入相同的问答、图解、练习流程。

模型生成需要等待。录制时可以保留发起与完成的画面，并用明确的“等待生成后”字幕衔接；不要把预制内容伪装成当场瞬间生成。

## 7:30–8:40　用户交互过程与成效

回到同一个学习空间，展示实际保存的题目记录、提示标记、错题与笔记。对照开始时的问题：“我分不清前序和中序”，现在能指出根的访问时机，沿图解推导结果，并完成本节练习。

总结本次可观察的结果：有原文依据的讲解、有可重播的过程图、真实提交的练习记录，以及可导出的个人笔记。这些是功能演示和一次学习过程的证据。若要宣称提高成绩、提升学习效率，需要另做真实用户实验，不能用演示数据编造提升百分比。

录制前打开项目并测试 API；准备一份可读文字的资料；避免展示 API 密钥、桌面私人文件或日志中的本机路径。可预先准备一组学习记录，以免录制时被模型等待时间打断，但要明确其为之前真实完成的学习内容。
