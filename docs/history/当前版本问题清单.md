# BookMind 当前版本问题清单

记录日期：2026-10-28。范围：`BookMind-v3`，基于 BookMind 原版源码删减和关联后的初版；本次整理不修改功能代码。

此文档记录的是 Git 快照 `snapshot/2026-10-28-native-v1` 的问题。后续已进行自主学习与 AI 导学改版，具体已处理事项及保留边界见 [AI 导学改版说明](AI导学改版说明.md)，本清单保留用于对照。

## 当前版本已经具备的基础

- Reading、Mastery Path 和 Notebook 使用原版核心实现，按教材 ID、学习路径 ID、笔记本 ID 和知识点来源建立联系。
- 阅读小测、Mastery 作答和复习安排使用原版学习证据与评估机制，不另建一套掌握分数。
- 当前采用文字模型。教材按页/节提取文字，目录初始化学习目标，模型按需读取原文并进行文本搜索；未配置嵌入模型。

## 需要继续处理的问题

### 1. 品牌改名没有完成

现象：前台主要入口使用 BookMind，但原版 API 默认定义、登录/注册页、部分设置说明、教学提示词和项目元数据中仍有 BookMind 名称。例如：

- `bookmind/api/main.py`：上游默认 API 标题和欢迎信息；BookMind 入口已覆盖运行时标题，但内部定义和欢迎文案仍需清理。
- `web/app/(auth)/register/page.tsx`：注册页品牌文字。
- `web/features/settings/navigation/settings-nav.ts`：部分设置说明。
- `bookmind/capabilities/mastery/prompts/zh/mastery_loop.yaml`：教学提示词。
- `pyproject.toml`：发行包名称及描述。

后续应分类处理：用户可见文字和模型身份统一为 **BookMind**；Python 包名、导入路径、命令入口、环境变量及存储键属于内部兼容命名，需要核对依赖和迁移方式；上游版权、许可证、来源链接和历史说明保留。不能用一次全文替换代替迁移。

### 2. 外层布局与原版组件的视觉整合不足

原版主要阅读、聊天与笔记组件被保留，但字体加载改成本机字体，并增加了教材标题、共同学习目标和导航区域。内部组件未随可用空间重新调整，出现字体观感、留白、信息密度和图文比例不协调。

用户截图还显示，大段说明与独立图解卡片之间缺少清晰的视觉层级，图内文字偏小。图解内部排版也受模型生成结果影响，应与固定界面的样式问题分别检查。

### 3. Mastery Path 的页面命名与实际职责不符

当前入口叫“练习 · Mastery Path”，实际包含大纲编辑、引导学习、理解检查、掌握判断和到期复习。它承担的职责多于独立刷题页，容易让用户误解。

后续需要明确引导学习、专项练习和错题复习的入口与文案。Reading 与 Mastery 复用聊天组件是原版设计；两者的会话、工作模式、工具和学习状态不同，复用输入框本身不是问题。

### 4. 聊天模式与出题入口的分工不清晰

Reading 保留普通聊天、出题、可视化等模式，同时还有阅读随堂测、Mastery 题卡和错题复练。模式切换会影响后端任务流程，但用户难以从界面判断各入口的差别，以及结果是否进入学习证据。

后续应让入口体现具体学习目的，并准确说明结构化测验与普通聊天中生成题目的记录差异。

### 5. Mastery 的原文引用展示未完整接通

模型已经可以读取绑定教材的原文，并在讨论中提及页码或段落；Mastery 页面没有同时接入 Reading 的完整原文阅读、定位与引用展示链路。用户因而可能看到引用说明，却不方便核对对应原文。

后续需要连接原文查看与定位，并区分模型写出的页码文字和有实际读取证据支持的来源。不能把引用文字本身当作引用已验证。

### 6. 教材检索与知识点初始化存在明确边界

- 当前通过按页读取、目录导航、原文片段和文字匹配搜索获取教材内容，没有完整复刻知识库的语义向量检索。换一种说法搜索以及跨章节寻找相关内容的能力需要进一步评估。
- 初始目标来自目录，默认按概念类型建立，尚未逐项细化为准确的概念、方法或其他学习目标。
- 目录条目及其页码范围只是学习骨架，不代表模型已经分析和理解全书；目标重编后仍需保留可靠的来源关系。

这些属于当前方案的能力边界，不表示出题或引导教学必须先配置嵌入模型。

### 7. 模型对工具能力的说明需要核实

用户截图中，模型声称“教材 PDF 不在工作区文件系统，所以不能提取原图”。教材实际由后端资料服务管理，该说法不能作为已核实的软件事实。后续应检查实际工具调用及权限，避免模型把当前没有使用某项工具解释为整个软件没有该能力。

当前不扩展图像理解、语音或图像生成服务，继续采用文字模型生成图解的范围。

### 8. 功能删减主要完成了入口与路由层，仍保留较多上游代码

全局聊天首页、伙伴、协同写作等独立功能已从当前应用入口移除，但相关共享模块、部分设置代码和依赖仍在源码中。后续需要按依赖关系继续清理，并明确真正保留的运行范围；源码中存在某模块不代表当前产品已经开放该功能。

## 按用户意见保留的设计

- 文字笔记与生成图解分开保存沿用原版设计，本轮不把它列为缺陷，也不要求合并成富文本笔记。
- 阅读中的标注与保存的引用原本共享同一标注存储，界面只是按类型筛选。“标注/摘录”和“回答中的来源引用”需要表达清楚；是否简化标签后续再评估，不认定为存储错误。
- 保留现有绿色芽苗图标，产品名使用 **BookMind**。
- 继续复制原版源码后删减、修改的路线，不回到独立重写三套核心模块的方案。

## 本次版本保存与验证范围

本次仅新增问题清单和 README 索引，功能代码保持当前状态。此前的测试与真实模型联调记录见 [新版验证记录](新版验证记录.md)；此前检查通过不代表上述交互问题已经解决。本次文档提交检查差异、格式和暂存文件范围，不重复运行模型调用或功能测试。

API 密钥、上传教材、聊天及学习数据、依赖和缓存继续由 `.gitignore` 排除。Git 保存源码和文档，不包含这些本机运行数据。
