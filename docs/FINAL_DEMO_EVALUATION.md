# BookMind 决赛验收、Trace 与五分钟演示

本文是展示前的可执行清单，不是已经完成的效果声明。每个案例只有在人工核对后才可标为通过，并应附上对应的 Run ID 或截图文件名。

## 核心创新：证据驱动的持续学习画像

BookMind 不把“答对一次”或“看过讲解”包装成完全掌握。每个学习单元同时维护三层信息：

1. **不可变事实**：独立作答、判分结果、提示、跳过、查看讲解、题后追问以及发生时间；
2. **确定性学习状态**：L1--L4、薄弱/待验证/待复验，仅由服务端 Evidence Gate 依据合格的独立作答更新；
3. **可替换学习画像**：LLM 基于上述事实写出的“已经观察到什么、当前不足、下一步验证目标、依据哪些事实”。

因此，“不足和下一步建议”不是一次回答末尾的临时文案，而是与证据关联、随新作答更新、能重新进入出题和讲解上下文的长期学习记忆。LLM 只解释事实，不能越权更改 L1--L4。这一分层既保留个性化，也避免模型自行宣称学生已经掌握。

## Trace 截图规范

每张截图只展示脱敏的 `/api/runs/{run_id}/trace/markdown` 页面，不展示 API Key、完整学生答案、完整 Prompt 或完整模型回复。

建议保留四张：

1. **问答决策**：知识点解析 → 检索约束 → 引用校验 → 回答完成；
2. **错误诊断**：提交答案 → FIFO/LIFO 误区信号 → 学习状态未升级的原因；
3. **补救验证**：诊断题 → 补救题 → 换情境验证 → 状态变化；
4. **边界案例**：AMBIGUOUS 指代要求澄清，或提示后作答不算独立证据。

本地开发排查可启用 `trace_capture_content` 并访问 `/api/runs/{run_id}/trace/debug` 查看模型 I/O 和 token；答辩截图使用默认脱敏 Trace。usage 未由模型返回时应显示“未返回”，不能按 0 统计。

## 五分钟演示脚本

| 时间 | 演示 | 评委应看到的因果关系 |
| --- | --- | --- |
| 0:00--0:35 | 打开已导入教材、目录与学习档案 | 教材是可溯源资料，而非无依据聊天 |
| 0:35--1:10 | 问“队列有什么用”，再问“它和栈有什么区别” | 先解析问题，再约束检索；追问连续但不会污染新话题 |
| 1:10--2:00 | 按队列出题，故意答“从队尾出队” | 系统识别可观察的 FIFO/LIFO 混淆，而非只说“错了” |
| 2:00--3:00 | 展示诊断与针对性补救，再答医院叫号/BFS 换情境题 | 补救改变下一题，且通过不同情境验证，不是重复背答案 |
| 3:00--3:45 | 打开学习档案 | 事实、确定性等级、LLM 画像分层；不足与下一步建议会被持续维护 |
| 3:45--4:30 | 打开一条脱敏 Trace | Agent/规则/检索分别做了什么，为什么状态更新或未更新 |
| 4:30--5:00 | 展示边界案例和评测表 | 说明提示/讲解不算独立证据，模型不稳定时安全降级 |
